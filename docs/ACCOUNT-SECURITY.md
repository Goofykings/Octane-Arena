# Account security review

Reviewed implementation and exercised it with the local API and isolated browser tests, September 27, 2026. This is a code/test review, not an independent penetration test.

| Area        | Implemented control and verification                                                                                                                                                                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Passwords   | Argon2id with per-password random salt, 64 MiB memory, three iterations, one lane; only encoded hashes stored. 8–128 characters, no composition restrictions. Database inspected for hash format and absence of the test password.                                       |
| Login       | Display-preserving, case-insensitive ASCII username lookup; database UNIQUE constraint handles racing duplicate registrations. Wrong/unknown accounts share a generic failure; unknown usernames still verify against a dummy Argon2id hash.                             |
| Abuse       | Registration/login limited to eight requests per minute per IP per route; global 180/min; four concurrent password jobs maximum, 32 KiB body limit. Production proxy trust is explicit. Limits need deployment monitoring and shared counters before horizontal scaling. |
| SQL         | Parameterized statements for every client value. Static schema SQL only. Invalid/injection-shaped usernames rejected. Multi-table saves use immediate transactions and rollback.                                                                                         |
| Authority   | Strict shared schemas reject extra XP/level/inventory/rank fields. Server checks each preset's items and title against owned rows. No client award or admin endpoints. Locked-title and stale-revision requests tested.                                                  |
| Sessions    | 256-bit random opaque token; only SHA-256 digest in database. HTTP-only cookies, Secure and \_\_Host scope in production. Expiry, rotation, revocation and max ten sessions/account. Tokens/hashes excluded from account responses.                                      |
| CSRF/CORS   | Exact allowlist, credentialed CORS, required mutation Origin plus custom header/JSON. Missing/hostile origins rejected; allowed preflight tested. No wildcard production CORS.                                                                                           |
| Errors/logs | Request logging disabled. No credential/body/stack logging. Internal failures return generic 503; validation, conflict, unauthorized, rate-limit errors use bounded messages. Injected database failure tested.                                                          |
| Frontend    | Original SVG avatar IDs only, username inserted with textContent; passwords sent only over HTTPS in production and never persisted by application JS. No session token in localStorage. Public frontend config contains an address only.                                 |
| Saves       | Atomic revision checks prevent blind overwrites across browsers. Guest local saves are kept separate from account data. Shared client/server validation; server remains authoritative.                                                                                   |
| Backups     | Online SQLite backup, explicit restore procedure, protected private files ignored by version control. Tested backup and restart persistence.                                                                                                                             |

Remaining deployment work: choose real HTTPS addresses, configure TLS/proxy/filesystem access and backup scheduling, and verify cookies in supported browsers. There is no email verification, password recovery, two-factor authentication, account deletion workflow, or multi-worker abuse store yet. Do not present those capabilities as available. XP awards, ranks and unlock evaluation are reserved for future trusted server match logic.

Design references: [node-argon2](https://github.com/ranisalt/node-argon2), [Node SQLite](https://nodejs.org/api/sqlite.html), [Fastify validation](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/), [OWASP session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).
